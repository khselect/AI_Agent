레버 4가지 — 효과와 트레이드오프

① 모델 축소 (최대 레버)
필드 추출은 깊은 추론이 아니라 구조화 작업. 30b→7b로 3배 이상 빨라짐. 39/43 추출률이 유지되는지 골든셋으로 검증 후 확정.
② 배치 5→3
프리필 반복 횟수가 곧 비용. 배치를 묶어 호출을 줄임. 너무 줄이면(1~2) 소형 모델의 JSON 정확도가 떨어지니 3배치가 균형점.
③ num_ctx 하향
배치 슬라이스가 최대 12,000자(≈6k토큰)이므로 16384면 충분. KV 캐시 축소로 메모리 압박·스왑 완화 — 30b에서 특히 효과.
④ 모델 상주(keep_alive)
50파일 연속 처리 시 파일마다 30b 재로딩을 막음. keep_alive="30m"으로 한 번 로드해 계속 사용 → 파일 간 로딩 오버헤드 제거.

개선 ② — 배치 루프를 CLI로 분리 (batch_ingest.py)

8시간(현재 설정) 또는 3~4시간(개선 후) 작업을 웹 세션이 아닌 독립 프로세스에. 모델은 한 번만 로드.
# batch_ingest.py — python batch_ingest.py ./reports --model qwen2.5:7b-instruct
import hashlib, os, sys, glob, json, time
from safety_analytics import extract_from_pdf, BATCHES_3
from safety_core import insert_accident

folder, model = sys.argv[1], "qwen2.5:7b-instruct"
files = sorted(glob.glob(f"{folder}/*.pdf"), key=lambda f: os.stat(f).st_mtime)
done  = load_registry()                             # 처리완료 해시셋 (재개용)

for i, f in enumerate(files):
    raw = open(f,'rb').read()
    h   = hashlib.sha256(raw).hexdigest()           # 내용 해시 중복배제
    if h in done: continue

    write_status(i, len(files), f, "running")      # status.json ← UI가 폴링
    data,_ = extract_from_pdf(raw, model,
                 batches=BATCHES_3, num_ctx=16384,   ①②③ 개선 설정
                 keep_alive="30m")               ④ 모델 상주 → 파일마다 재로딩 X
    insert_accident(data, f, file_hash=h)           # 파일단위 즉시 커밋
    record_registry(h, f)
    write_status(i+1, len(files), f, "done")
