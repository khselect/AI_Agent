현재 에이전트는 DB(사고 이력)는 잘 쓰지만 "권위 있는 근거"가 없습니다. 그래서 출력이 데이터 기반이긴 해도 규정 근거는 비어 있습니다. 매뉴얼·법령을 미리 벡터DB로 색인하고 검색 툴 하나를 추가하면, 같은 워크플로우가 "○○법 제△조 근거"를 인용하는 감사 대응 가능 수준의 전문 출력으로 바뀝니다.

아키텍처 — 색인(오프라인) + 검색(런타임)

색인은 문서가 바뀔 때만 1회. 검색은 에이전트가 필요할 때 호출하는 8번째 툴.
① 색인 파이프라인 (오프라인·1회)
매뉴얼·법령 PDF/HWP → 파싱 → 조·항 단위 청킹 → 임베딩(bge-m3) → 벡터DB 적재. 청크마다 메타데이터(문서명·조번호·개정일·소관부서·버전) 부착.
② 검색 툴 (런타임·에이전트 호출)
질의를 임베딩 → 코사인 유사도 상위 k개 조항 반환(본문 + 출처 메타). 에이전트가 query_db_tool로 사고 데이터를, retrieve_regulation_tool로 규정 근거를 함께 확보.

검색 툴 — DuckDB VSS로 인프라 최소 추가

이미 DuckDB를 쓰므로 vss 확장만 붙이면 별도 벡터DB 서버가 필요 없습니다.
# railway_safety_agent.py — 8번째 툴
@tool
def retrieve_regulation_tool(query: str, top_k: int = 5, doc_type: str = "all") -> str:
    """철도안전법·기관 매뉴얼 벡터DB에서 질의와 관련된 조항을 검색."""
    emb  = ollama.embeddings(model="bge-m3", prompt=query)["embedding"]  ① 로컬 임베딩
    conn = duckdb.connect(KB_PATH, read_only=True)
    rows = conn.execute("""
        SELECT 문서명, 조항, 본문, 개정일, doc_type,
               array_cosine_similarity(embedding, ?::FLOAT[1024]) AS score
        FROM regulations
        WHERE (? = 'all' OR doc_type = ?)
        ORDER BY score DESC LIMIT ?""", [emb, doc_type, doc_type, top_k]).fetchall()  ② VSS 검색
    return json.dumps(  ③ 본문 + 출처 메타 반환 → 인용 강제
        [{"조항":r[1], "본문":r[2], "출처":f"{r[0]} ({r[3]} 개정)"} for r in rows],
        ensure_ascii=False)
인용 강제 프롬프트
시스템 프롬프트에 규칙 추가: "규정 관련 판단은 반드시 retrieve_regulation_tool로 근거 조항을 확보한 뒤, 출처(문서명·조번호·개정일)를 명시하라. 검색 결과에 근거가 없으면 단정하지 말고 '해당 규정 확인 필요'로 표기하라." → 환각·구버전 인용 방지.

설계 고려사항 · 리스크

청킹 전략
법령은 조·항·호 단위, 매뉴얼은 절 단위로 분할. 한 청크에 여러 조가 섞이면 검색 정확도·인용 정합성이 무너짐.
한국어 임베딩
bge-m3(다국어·1024d) 또는 KURE·ko-sbert. 로컬 Ollama/sentence-transformers로 온프레 유지 — 기존 온프레 지향과 부합.
최신성·버전 관리
법 개정 시 해당 조항만 재색인. 메타의 개정일을 출력에 노출해 구버전 인용을 즉시 식별.
보안·접근권한
내부 매뉴얼은 온프레 벡터DB에만 적재, 외부 전송 금지. 발송 메일에 대외비 조항 원문 포함 여부를 등급별로 통제.
검색 품질 평가
"이 사고 유형 → 정답 조항" 소규모 골든셋으로 top-k 정확도 측정. hybrid(키워드+벡터)로 조번호 정확 매칭 보완.
법적 책임 경계
출력은 근거 제시·의사결정 보조까지. "법 위반 확정" 같은 단정은 배제하고 담당자 검토 전제 문구를 표준화.

단계적 로드맵

Phase 1 · 파일럿
철도안전법 1종만 색인. DuckDB VSS + bge-m3. retrieve_regulation_tool 등록, 골든셋으로 검색 정확도 확인.
Phase 2 · 확장
기관 매뉴얼·시행규칙·내규 추가. 워크플로우 goal_template에 "근거 조항 인용" 지시 삽입, 레포트에 출처 각주.
Phase 3 · 운영
개정 자동 재색인, 규정 대비 gap 분석, 감사 로그(어떤 조항이 어떤 판단에 쓰였는지) 보관.
